# pUI · 技术选型与架构设计

> 状态:初稿(2026-08-07)。对应 PRD:`docs/prd/pUI-v1-产品需求文档.md`。

## 1. 技术栈总览

| 层 | 选型 | 理由 |
|---|---|---|
| 桌面外壳 | **Tauri 2** | 安装包小(~10MB)、内存低、跨 Win/macOS/Linux;Rust 后端薄 |
| 前端 | **React + TypeScript + Vite** | 生态成熟、类型安全;UI 为纯前端逻辑 |
| 前端状态 | **Zustand**(或 React Context) | 轻量、无需样板 |
| 解析引擎 | **tshark**(打包内置) | ~3000 协议 dissector、原生 pcapng/gzip、字段可定制导出 |
| 时序图渲染 | **React 自绘 SVG** | 两端点时序图数据量小,自绘样式/交互完全可控,天然支持 A/B 双风格 |
| 测试 | **Vitest**(前端) + **Rust 单测** + 集成测试 | TDD(见 AGENTS.md) |

## 2. 为什么选 Tauri + tshark

- **Tauri 而非 Electron**:团队内部分享场景,安装包体积与内存是关键差异(Tauri ~10MB vs Electron ~100MB+)。Rust 后端只做「调 tshark 子进程 + 读输出」,代码量小。
- **tshark 而非自研解析**:自研解析器只能覆盖 IP/TCP/UDP + 少量应用层,pcapng 支持残缺;tshark 提供业界最全协议覆盖与成熟字段体系。代价是分发一个 tshark 二进制(~15MB)与 GPL 合规(见决策记录)。
- **自绘 SVG 而非图库**:一个会话仅两端点、一条消息一个箭头;自绘能精确实现编号/时间戳/长度/方向色/协议色/悬停/点击详情,且 A/B 两套布局共用同一数据源。

## 3. 模块划分与数据流

```
open_capture(path)
   │  invoke
   ▼
后端(Rust):tshark -r <path> -T json <固定字段集>  →  JSON 字符串
   │  invoke 返回
   ▼
前端:parseJSON → Packet[]
   │
   ├─ 会话聚合器(纯函数)→ Conversation[](双向流归一化 + 客户端判定)
   ├─ 筛选器(纯函数):FilterCondition × Conversation → 命中会话集
   ├─ 会话列表渲染
   ├─ 选中会话 → 时序图渲染器(SVG,风格 A/B)→ 交互(悬停/点击)
   │       │
   │       └─ 点击报文 → invoke fetch_hex(number) → tshark -x → hex dump → 详情条
   └─ 导出 PNG:SVG → canvas → PNG(前端)
```

**要点**:
- **解析一次,前端处理**:文件打开时 tshark 一次性导出全部报文 JSON;会话聚合与筛选都在前端纯函数完成(常规抓包规模 ≤ 几十万报文,内存与计算可承受)。
- **hex 按需**:不随打开全量拉取;点击报文时单次调 tshark `-x` 获取。
- **tshark 定位优先级**:① 随包内置资源目录 → ② 用户配置路径 → ③ 系统 PATH;未找到时走降级引导(§6)。

## 4. 前后端接口(命令面)

```ts
// Tauri commands(Rust 侧)
open_capture(path: string): CaptureMeta          // 返回文件概览 + Packet[]
fetch_hex(path: string, frameNumber: number): string  // hexdump 文本
locate_tshark(): string | null                   // 返回可用的 tshark 路径
set_tshark_path(path: string): void              // 用户手动指定
```

## 5. 关键实现细节

### 5.1 tshark 输出解析
- 打开:`tshark -r <file> -T json` + `-e`/`-J` 限定字段集(PRD §11.5),避免 HTTP body 等大字段撑爆输出。
- 前端将 JSON 映射为 `Packet[]`(PRD §11.1),缺失字段置 undefined。
- 会话聚合:`Map<key, Conversation>`,`key = sort((ipA:portA),(ipB:portB))` 的规范化串;同时记录发起方以推导 direction。
- 客户端判定:TCP 找先发 SYN 者 → 低端口 → 首包发送者;UDP 首包发送者;ICMP/ARP 仅方向。

### 5.2 时序图渲染(SVG)
- 数据源:一个会话的 `Packet[]`(时间升序)。
- 布局函数 A/B:`layoutSlanted(packets)` / `layoutRows(packets)`,产出带几何坐标的消息模型,再由渲染组件画线/箭头/标注。
- 编号 = 会话内可见时间序(① ② ③…);时间 = 相对首包(可切绝对)。
- 配色:协议色(线)、方向色(徽章/箭头),来自 PRD §11.4 调色板;支持「整线按方向着色」切换。
- 交互:悬停高亮 + tooltip;点击 → 详情条;垂直缩放(基于视口 + scroll);>2000 报文提示。
- 导出 PNG:`svg → XMLSerializer → Image → canvas → toBlob('image/png')`。

### 5.3 筛选器
- `FilterCondition`(PRD §11.3)→ 对 `Conversation[]` 过滤:会话内任一 Packet 满足所有维度(AND)+ 任选值(OR)+ 取反。
- 维度归一化:端口条件同时匹配 `tcp.port/udp.port`;地址匹配 `ip/ipv6`。

## 6. 错误处理策略

| 场景 | 处理 |
|---|---|
| 文件不可读 / tshark 解析失败 | 返回结构化错误,弹窗展示摘要 |
| tshark 未找到 | 引导:设置路径 / 检测 Wireshark 安装目录(注册表/PATH/常见目录) |
| 筛选空结果 / 无会话 | 空态视图 + 引导 |
| 详情/hex 拉取失败 | 详情条降级,不阻塞主界面 |
| tshark 进程超时/崩溃 | 捕获退出码与 stderr,提示后允许重试 |

## 7. 工程目录结构(规划)

```
pUI/
├─ docs/                    # 文档(按类分目录)
├─ prototype/               # 原始原型图(flow.png / prototype.jpg)
├─ src/                     # 前端(React + TS + Vite)
│  ├─ model/                # Packet / Conversation / FilterCondition 类型
│  ├─ parse/                # tshark JSON → Packet[]
│  ├─ aggregate/            # 会话聚合(纯函数)
│  ├─ filter/               # 筛选器(纯函数)
│  ├─ render/               # 时序图 SVG 组件 + layoutA/layoutB
│  ├─ detail/               # 报文详情条 / hex 视图
│  ├─ state/                # Zustand store
│  └─ app/                  # 布局(三栏)、工具栏
├─ src-tauri/               # Rust 后端 + 打包
│  ├─ src/                  # commands、tshark 封装
│  └─ resources/            # 内置 tshark 二进制 + LICENSE
└─ fixtures/                # 内置示例抓包(集成测试 + F7)
```

## 8. 测试策略(TDD)

- **前端单测(Vitest)**
  - `parse`:tshark JSON fixture → Packet[] 字段正确。
  - `aggregate`:五元组双向归并、客户端判定(TCP SYN/低端口/首包)、ICMP/ARP 归一。
  - `filter`:AND/OR/取反、端口双协议匹配、非 IP 降级。
  - `render`:layoutA/layoutB 对给定报文产出正确 SVG 结构(编号、方向、长度标注、方向色)。
- **后端单测(Rust)**:tshark 命令构建、JSON 解析、错误处理。
- **集成测试**:fixtures 样例 pcap 全流程(打开→筛选→会话→时序→详情→导出),端到端断言。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| tshark 二进制跨平台差异 | 按平台打包对应二进制;定位逻辑统一抽象 |
| GPL 合规 | 子进程隔离 + 随包附带许可证文本(见决策记录) |
| 大文件内存 | v1 面向常规规模;预留「筛选下推 tshark -Y」优化路径(v1.1) |
| 协议字段映射维护 | 固定字段集 + 前端类型化;新增协议只需扩展字段映射 |
