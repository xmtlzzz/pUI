## High 级(H1-H8,按修复批次归组)

### 批 1 · Rust 防挂死(C1-C4)

1. **[High] 全部命令为同步 fn,跑在 Tauri 主线程** — commands.rs:15,20,35,82,102,113。tshark 解析(≤128MB JSON)/base64 解码(≤192MB)/where spawn 期间整窗 UI 硬冻结。
   修复:命令改 async fn + tauri::async_runtime::spawn_blocking;状态改 Arc<AppState> 共享。
2. **[High] run_stream 先读尽 stdout 再读 stderr,stderr 管道写满即死锁** — tshark.rs:69-101。畸形 pcap 的错误风暴(>64KB stderr)让 tshark 阻塞在写 stderr,stdout 永不 EOF,父进程永久阻塞;wait() 同样因 stderr 未排空卡死。注释「stderr 只用于短错误」对错误风暴型文件不成立。
   修复:并发线程排空 stderr(读入 String 用于诊断)。
3. **[High] 子进程无墙钟超时** — tshark.rs:69-132。tshark 读 FIFO/设备、病态 section length、卡慢 IO 时调用线程永久阻塞,线程+进程泄漏,无恢复路径。
   修复:轮询 try_wait + 截止时间,超时 kill+wait 返回可读错误。
4. **[Med] run_hex 走 .output() 全量缓冲,单帧 hex 无上限** — tshark.rs:103-109。恶意 pcapng 可声明 caplen≈512MB, -x 输出 3-4 倍文本 → 一次分配 1.5-2GB OOM,绕过 run_capture 唯一防线。
   修复:run_hex 复用 run_stream,hex 文本上限 32MB。

### 批 2 · 前端会话正确性(A1-A2 + M)

5. **[High] flowKey 端点评判不对称,同一 TCP/UDP 流被拆成两个会话** — aggregateConversations.ts:5-24。side() 要求双侧端口齐全才用 ip:port,b 分支只要求 dst 侧;任一端口缺失(畸形/截断帧、ICMP 错误回显内嵌 TCP 头)时两方向 key 不同 → 拆成两个单向会话 → 假 one-way/unanswered、字节统计拆半。已实验复现。
   修复:两侧统一复用 sideOf(p,true)/sideOf(p,false) 后字典序归一。
6. **[High] SYN 判定对 tcp.flags 形态脆弱** — parsePackets.ts:7-9,52-64。tcp.flags 为嵌套对象(jsonraw/部分旧版 tshark)时 first() 返回对象,parseInt 恒 NaN,SYN 检测全线静默熄灭,client/server 退化到端口启发式可反转,syn-no-reply 不再触发。
   修复:first() 遇对象 unwrap(tcp.flags / tcp.flags.str);或 tcpInfo/SYN 判定处容错。
7. **[Med] frame.protocols 缺失时 proto 为空串而非 unknown** — parsePackets.ts:121。脏数据扩散到会话 protocol/bestProto/图例/筛选/配色哈希。修复:空段视为 unknown。

### 批 3 · 展示层(B1-B2 + M)

8. **[High] 导出 PNG 直接 OOM** — exportPng.ts:44-55。canvas 尺寸取 viewBox 全量 = 520×(72+30n)px;n=5000 → 312MB RGBA,n=20000 → >1GB 崩溃。>2000 报文仅提示不降级。
   修复:导出前按固定上限等比抽稀 + 高度封顶(如 8000px)或提示先筛选。
9. **[High] zoom 缩放造成滚动死区,下半图不可达** — SequenceDiagram.tsx:65-70 + layout.ts:35。CSS transform: scale(zoom) 不改盒尺寸,滚动容器仍按未缩放高度算 scrollHeight;zoom=3 时约 2/3 内容永远滚不到,瓦解「报文多建议缩放」提示。
   修复:缩放后同步 svg width/height = layout×zoom。
10. **[Med] hover 每次 O(n) 全量重排** — SequenceDiagram.tsx:28,91-99。layoutSequence/protos 无 useMemo,每次 render(含 mouseenter)全量重映射 + 全量 React diff;数千报文鼠标划过即卡。
    修复:useMemo + hover 只存 id + <g> 包 memo。
11. **[Med] hexCache 无限增长** — appStore.ts:110-119。只在新文件加载清空,长会话反复浏览内存只增不减。修复:LRU(200 条/8MB)。
12. **[Med] 会话列表无虚拟化** — ConversationList.tsx:37-66。数万会话 DOM 爆炸;tbody key=JSON.stringify(filter) 每次筛选整体重挂载。修复:窗口化或截断前 1000+提示。
13. **[Med] IPv6:port 被 displayHost 当裸 IPv6 展示** — model/types.ts:114-131。'2001:db8::1:443' 含 :: 且各组合法 → isBareIpv6 true → 端口混进端点标签(IPv4 却剥端口);不影响方向判定(两侧同串)。修复:displayHost 对带端口串优先拆端口。
14. **[Med] 拖拽 overlay 闪烁** — AppLayout.tsx:126-131。onDragLeave 挂整层,经过子元素反复触发。修复:enter 计数或 relatedTarget 判断。
15. **[Med] FilterSelect 键盘可达性残缺** — FilterSelect.tsx:53-116。焦点不进入菜单、无方向键、Tab 移出不关闭、chip 不可聚焦。修复:焦点管理 + Arrow 导航 + Tab 关闭 + chip 改 button。

### 批 4 · 误报抑制(A3 + M)

16. **[High] no-close/lost-segment/retransmission 对中途抓包片段系统性误报** — issues.ts:35-47。任何无 FIN 片段必报 no-close;tshark 流起始处给首个数据段打 lost-segment/retransmission 是公认假阳性,代码无条件信任。真实 pcap 最常见的「中途开始抓包」形态被成批误报进「仅看异常」。
    修复:首包无 SYN 且 tcp.seq 非 0 时抑制 no-close;lost-segment 仅在有可对照前序时报告;message 标注「捕获首个报文即数据段」。
17. **[Med] one-way 被 if(!issues.length) 抑制** — issues.ts:83-88。「仅请求+重传」会话只报 retransmission,永不报「未收到任何响应」——恰是该会话最该呈现的结论。修复:独立判定,与其它 issue 并存。
18. **[Med] RST 抑制只覆盖 SYN,HTTP/DNS unanswered 双重误报** — issues.ts:31 vs 62-66/76-80。连接被拒场景显式拒绝被标成「未收到响应(可能丢包)」。修复:unanswered 追加 !rst 条件(与 SYN 对称)。
19. **[Med] HTTP 无响应/慢响应完全依赖 tshark 解码完整性** — issues.ts:62-73。HTTP/2、未重组分块响应缺 code 即误报;http.time 缺失则 slow-response 永不触发;阈值 1.0s 硬编码。修复:unanswered 仅在有双向数据证据/超时窗口时报告,阈值可配置。

## 测试对抗结论

- 现有 79 项测试全绿,但存在系统性盲区(High 级因此溜进发布):issues 测试 100% 从 SYN 黄金路径开始;SequenceDiagram 测试只测 3 条报文节点存在性;exportPng 从未真解码出图(jsdom 无 canvas);tauri 浏览器回退路径零覆盖;FilterPanel 测试依赖「menu 不关闭」才成立;protocolColors 断言碰巧不撞而非保证语义。
- 已核查不成立项:selectSelected 无新引用问题;filtered 无过期路径;loadSeq 令牌正确;无 XSS 面(全文本节点);resizer 清理完整;DNS direction 时序无问题(aggregate 先赋 direction 再 analyze)。

## Top-5 优先修复(跨范围合并)

1. Rust:命令 async + spawn_blocking + 子进程超时(kill+reap) — 消除「打开畸形 pcap 永久冻结」
2. run_stream 并发排空 stderr(或丢弃)+ 超时兜底
3. flowKey 两侧规则统一 — 一行级改动根除静默拆会话/假 one-way
4. 导出高度封顶 + zoom 盒尺寸同步 — 稳定复现的崩溃/不可达
5. 中途抓包片段 no-close/lost-segment 抑制 — 决定「仅看异常」真实性
