# 参考实现与竞品分析

> 状态:初稿(2026-08-07)。本文基于既有开源项目的公开知识整理,撰写时本会话网络受限未做实时核验;正式开发前建议在联网环境复核各项目最新状态与 license。

## 1. 直接对标:Wireshark / TShark

- **Wireshark「统计 → 流量图(Flow Graph)」**:即「时序(sequence)视图」——把选中范围的报文画成端点列 + 时间轴的有向线,方向即报文方向。与本产品 F4 目标一致。
  - 借鉴:列式端点、按协议着色、按显示过滤生效。
  - 差距:Wireshark 该视图仅作为「统计」存在,交互有限(无详情联动、无双风格切换、样式朴素),且强依赖 Wireshark 桌面端。
- **TShark**:命令行版,`-T json` / `-T ek` / `-T fields -e <字段>` 可结构化导出;`-Y <display filter>` 原生过滤;`-r` 读 pcap/pcapng/gzip。
  - **定位:本产品的解析引擎**(约 3000 个协议 dissector,协议覆盖业界最强),不做任何自研解析。
- **Wireshark 关键约束**:GPL-2.0。若**打包 tshark 二进制随产品分发**,需注意 GPL 传染性要求——本项目只做「以子进程调用 tshark 引擎」的整合,不修改/不链接 tshark 代码,分发时随包附带许可证文本即可;若改为「要求用户自行安装 Wireshark」可彻底规避,但牺牲开箱即用。→ 详见 `docs/decisions/` 决策记录。

## 2. 会话/流程可视化类

- **Arkime(前 Moloch)** `github.com/arkime/arkime`
  - 大规模抓包 + 搜索 + Web 会话查看器;SPI graph 展示主机间连接;会话(session)为中心导航。
  - 借鉴:以「会话」为第一级导航(而非原始报文),先看会话再下钻。
  - 差距:重后端(Elasticsearch/OpenSearch 集群)、面向服务器端大流量,非轻量桌面工具。
- **NetworkMiner**
  - Windows GUI,主机/会话中心化的 pcap 分析,自动提取文件、凭证、凭据等。
  - 借鉴:主机维度视角;文件/内容提取思路(v1.2)。
  - 差距:Windows 限定、界面年代感强、时序交互弱。
- **tcpflow** `github.com/simsong/tcpflow`
  - 把 TCP 流重组为可读内容文件。借鉴:流(stream)概念;但其强项在重组内容(本产品 v1 不做重组)。
- **Zeek(Bro)** `github.com/zeek/zeek`
  - 网络分析框架,产生会话/连接日志(conn.log 含五元组、字节、时长)。
  - 借鉴:连接日志字段模型(与 F3 会话列高度一致)。
  - 差距:需部署分析框架,非交互式可视化。

## 3. 渲染技术选型参考

| 方案 | 适用 | 结论 |
|---|---|---|
| **自绘 SVG(React 组件)** | 两 lifeline + 有向箭头 + 精确标注/着色/交互 | ✅ v1 采用:数据量小、样式完全可控、双风格切换天然 |
| Mermaid `sequenceDiagram` | 快速出时序图 | 样式/交互受限,无法做方向着色与点击详情,不满足定制 |
| AntV G6 / X6 | 复杂图布局(多节点自动布局) | v1 会话仅两端点,杀鸡用牛刀;可作 v1.2 多主机拓扑图的候选 |
| React Flow(@xyflow/react) | 节点图工作流 | 同样是多节点场景;两端点时序图用不上 |

## 4. 借鉴清单(直接进入 PRD)

1. 会话(conversation/stream)作为第一级导航 —— Arkime、Zeek、Wireshark TCP stream。
2. 端点列 + 时间轴 + 有向线 —— Wireshark Flow Graph。
3. 结构化导出 + display filter —— TShark `-T json / -Y`。
4. 连接字段模型(五元组/包数/字节/时长) —— Zeek conn.log。
5. 主机/会话中心化视角 —— NetworkMiner。
6. GPL 分发合规 —— 随包附 tshark 许可证文本(见决策记录)。
