# M4 案例 2:乱序后补齐且无重传 —— 「乱序不等于丢包」对照页设计

> 状态:待审批(M4 三案例之一,审批前不进入 UI 编码)
> 数据源:`docs/specs/m4-cases/data/case-2-out-of-order.json`(已冻结,本文所有数值均出自该文件)
> 事件:`0:c2s:reordering:101` · kind=`reordering` · severity=`low` · recovered=`true` · evidenceScore=`5`
> 核心论点:tshark 给填补段 #7 打了 `retransmission` 标签,但序列空间证明它是迟到的原始段(`newBytes == seqLen == 100`,全新字节)。标签是 Observation,不是结论 —— 本案例把这场"对峙"做成核心分镜 S3。

全局规则:

1. **可暂停**(Space/⏸)、**可单步**(←/→ 或 ⏮⏭,跳至相邻分镜末态)、**可中断**(Esc、切换事件或离开页面即刻 kill timeline 并清理 tween)。
2. 所有动画仅 transform/opacity,作用于固定尺寸容器内部,**布局尺寸零变化**(Gap 显露/收缩用 scaleX,不撑开容器)。
3. **动画不承载唯一信息**:S0 已含全部分镜末态信息;任何 chip 文案在动画结束后常驻,不随 tween 回收。
4. **reduced-motion**(prefers-reduced-motion 或手动 ☐动画):跳过全部 tween 直接呈示各分镜末态,并提供「分镜步骤条」逐条文字版(S1…S5 各一行摘要),组件测试覆盖键位与等价性。

## 5. 数据保真声明

- **左栏全部为真实抓包数值**:包号 1–8、time、flags、raw seq/ack、len、tags、Gap(101→201/100B/约 0.002s)、`seenBytes`(c2s=301,s2c=1)、事件 id/severity/evidenceScore、`classificationSignals`(fillerCarriesOnlyNewBytes=true,durationSeconds≈0.002,duplicateAckCount=0)、观测 id 与字段值(o1/o2/o3)。
- **右栏全部为解释性示意**:R①–R⑨ 步骤号、节奏与时序均非本抓包数据;形态取自 `reference-normal.json` 的「握手 → 3 段各 100B 顺序到达 → ACK 逐段推进至 301」结构,截取至与左栏相同尺度(0–301)。右栏**永不使用真实 packet number**,seq 刻度以「≈」标注示意。
- 右栏内容**不写入** observations/inferences/limitations,不参与事件判定与排序,PNG/Markdown 导出时整栏排除;「正常参考/示意」徽标常显、不可关闭。
- 措辞与引擎一致:只说「未观察到重发」「符合迟到原始段形态」「缺口随后补齐」,不出现「确定性丢包」「网络丢了 B 段」;tshark 的 `lost-segment`/`retransmission` 标签一律以 Observation 灰阶呈现并注明来源是 tshark 标注;两条单观察点 Limitation 必须随事件卡展示。

## 审批记录(2026-08-26)

**结论:批准,附一条强化要求**(三案统一,全文见 case-1 审批记录)。

> 要求:报文交互过程必须有**明显的阶段标注**——时间线上把交互划分为命名清晰的故障阶段,
> 每个阶段的起止报文、持续时长、该阶段发生了什么都要在图形上直接可见。

本案例的阶段划分(由引擎事件链导出):

`① 顺序到达(#4–#5)` → `② 乱序暴露缺口(#6,C 先到)` →
`③ 迟到补齐(#7,B 到达;含「tshark 标签 vs 序列空间证据」对峙子阶段)` → `④ 直接恢复(#8,ACK 跳进 301)`

阶段带/当前阶段高亮/阶段信息面板的实现约束与验收方式同 case-1 审批记录第 4 条:
阶段边界从引擎输出确定性推导,视图模型层新增 stage 推导纯函数并有单测。
