# 关键决策记录(ADR)

> 记录 pUI 开发中的关键架构与产品决策。格式:状态、背景、决策、后果。最新在上。

## ADR-006 · 内置示例抓包(F7)

- **状态**:✅ 已定(2026-08-07)
- **背景**:使用场景含「教学 / 演示」,开箱即用体验需要示例。
- **决策**:v1.0 随包附带 2–3 个示例抓包(HTTP、DNS、ARP/TCP 混合),提供「打开示例」入口。
- **后果**:演示零门槛;示例同时用作集成测试 fixtures,一物两用。

## ADR-005 · 时序图双风格 A/B + 方向色(PRD §6 F4)

- **状态**:✅ 已定(2026-08-07,经可视化对比确认)
- **背景**:用户参考原型为 flow.png 斜线交叉风格;但报文多时交叉密集,可读性下降。
- **决策**:默认风格 A(flow.png 斜线交叉)+ 风格 B(水平消息行),一键切换;线色=协议色,方向用步骤徽章/箭头(请求蓝 ● / 响应橙 ●),可选整线按方向着色。
- **后果**:满足参考原型又保证可读性;渲染层按「同一数据源 + 两套布局函数」实现,切换零成本。

## ADR-004 · 三栏常驻布局(PRD §7)

- **状态**:✅ 已定(2026-08-07,经可视化对比确认)
- **背景**:三大核心内容(筛选 / 会话列表 / 时序图)需同屏协同。
- **决策**:三栏常驻(左筛选 | 中会话列表 | 右时序图)+ 顶部工具条。
- **后果**:筛选项始终可见、改筛选即时生效;窄屏下右图空间受限(可接受)。

## ADR-003 · 筛选语义 = 会话级(PRD §6 F2)

- **状态**:✅ 已定(2026-08-07)
- **背景**:「筛协议=X」到底画什么有歧义;几十万报文直接画图必爆炸。
- **决策**:两级粒度——筛选收敛「会话列表」,点进会话再看「报文时序图」;会话内任一报文命中即命中会话。
- **后果**:避免图爆炸,交互路径清晰;会话内报文过滤留作 v1.1。

## ADR-002 · 时序图渲染用自绘 SVG(PRD §9)

- **状态**:✅ 已定(2026-08-07)
- **背景**:需精确实现编号/时间/长度/方向色/协议色/悬停/点击详情/双风格。
- **决策**:React 自绘 SVG,不引入 Mermaid/G6/React Flow 等图库。
- **后果**:样式与交互 100% 可控、依赖少;两端点场景数据量小,自绘完全足够。

## ADR-001 · 技术栈:Tauri 2 + React + tshark 引擎

- **状态**:✅ 已定(2026-08-07,用户确认)
- **背景**:跨平台桌面工具,需安装包、小体积、开箱即用;解析需覆盖大量协议。
- **决策**:
  1. 桌面外壳 **Tauri 2**(vs Electron:安装包 ~10MB vs ~100MB+,内存低)。
  2. 解析引擎 **tshark 打包内置**(vs 自研解析:约 3000 协议覆盖 vs 几十种;pcapng/gzip 原生支持)。
  3. 前端 **React + TS + Vite**,后端 Rust 薄封装(调 tshark 子进程 + 读输出)。
- **后果**:
  - 依赖:分发需附 tshark 二进制(~15MB)与 GPL 许可证文本。
  - 隔离:tshark 以子进程调用,不修改/不链接其代码,仅整合分发,规避深层传染;随包附许可证文本(与 Wireshark/tshark 的 GPL-2.0 兼容做法)。
  - 前端做解析与聚合(文件规模小),后端保持薄。

## ADR-000 · 文档组织按类别分目录

- **状态**:✅ 已定(2026-08-07)
- **背景**:用户要求 PRD 及类似文档按类别归纳。
- **决策**:`/docs` 下按类别分子目录:`prd/` `research/` `architecture/` `decisions/` `specs/`(后续 writing-plans 产出)。
- **后果**:文档可检索、分类清晰;`prototype/` 保留原始原型。
