# pUI — 抓包报文时序分析工具 · 产品需求文档(PRD v1.0)

> 状态:✅ 已确认(2026-08-07)
> 作者:pUI 设计会话(brainstorming)
> 工作名:**pUI**(暂定,最终产品名可替换)

## 1. 背景与问题

用 Wireshark 抓包后,默认的报文列表视图(逐行:序号 / 时间 / 源 / 目的 / 协议 / 长度 / 信息)在信息密度高的场景下**「看内容并不明显」**——难以快速回答三个问题:

1. **谁和谁在通信?**(源 / 目的地址与端口)
2. **用的什么协议?走了什么流程?**(TCP 握手 → HTTP 请求 → 响应)
3. **一次交互先后发生了什么?**(报文 1 → 2 → 3 的次序与时间)

市面上现有工具要么是列表式(Wireshark),要么偏运维大平台(Arkime 等),缺少一个「**把一段会话的报文交互画成时序图、一眼看懂**」的轻量跨平台桌面工具。

## 2. 产品定位

**pUI** 是一款跨平台(Win / macOS / Linux)桌面工具:打开 pcap / pcapng 抓包文件,支持按 **协议 / 源地址 / 目的地址 / 源端口 / 目的端口** 多维筛选,把命中会话的**报文交互以时序图方式渲染**(报文按可见时间编号 1 → 2 → 3,箭头方向即真实方向),让「谁和谁、什么协议、怎样一来一回」一目了然。

纯本地运行,不上传任何数据。

## 3. 目标用户与使用场景

| 场景 | 说明 | 对产品的要求 |
|---|---|---|
| 自用 · 学习 / 调试 | 学习协议、调试本地服务,看清握手与请求响应 | 易懂、轻量、中文界面 |
| 教学 / 演示 | 给别人讲解报文交互 | 导出 PNG、内置示例抓包、界面精致 |
| 团队内部分享 | 分发给同事排查网络问题 | 安装包开箱即用、稳定、通用协议覆盖 |
| 安全分析 | 从安全角度初看抓包 | 报文详情完整、支持常见协议(深层次能力在后续版本) |

结论:v1 面向综合场景,交付**可安装的跨平台安装包 + 中文界面 + 内置示例抓包**。

## 5. 核心流程与用户故事

### 5.1 核心操作流

```
打开文件 → 左栏筛选 → 会话列表(中) → 点击会话 → 时序图(右,报文①→②→③) → 点击报文看详情 → 导出 PNG
```

### 5.2 用户故事

- **US-1** 作为用户,我打开一个 pcapng,能看到文件概览(报文数 / 接口 / 时间范围),以便判断抓包是否完整。
- **US-2** 作为用户,我按「协议 = HTTP、目的端口 = 80」筛选,会话列表只保留命中的会话,以便收敛分析范围。
- **US-3** 作为用户,我点进一个 HTTP 会话,看到 TCP 握手 + 请求 + 响应的完整时序图(① SYN → ② SYN-ACK → ③ ACK → ④ GET → ⑥ 200 OK …),以便理解交互过程。
- **US-4** 作为用户,我悬停某个报文看到概要、点击看到完整字段与 hex,以便核对细节。
- **US-5** 作为用户,我把时序图导出为 PNG,以便写文档或教学分享。
- **US-6** 作为用户,我打开一个 ARP 报文时,端口维度置灰,界面不报错,以便正常浏览非 IP 流量。

## 6. 功能需求

### F1 文件导入

- 支持 `.pcap` / `.pcapng` / 常见 `.gz` 压缩(`.pcap.gz` / `.pcapng.gz`)。
- 支持**拖拽文件到窗口**或点击「打开文件」选择。
- 解析引擎:**打包内置的 tshark**;若内置缺失,降级为「用户指定路径」或「检测系统已装 Wireshark/tshark」(见 §11)。
- 打开后顶部信息条显示:文件名、报文总数、接口数、时间范围、文件大小。
- 解析与加载有进度提示;解析失败给出明确错误(§11)。

### F2 多维筛选

- **维度**:协议、源地址、目的地址、源端口、目的端口(IPv4 / IPv6 通用)。
- **组合语义**:各维度之间为 **AND**;同一维度内多值可选为 **OR**;支持**取反(NOT)** 与一键**清除**。
- **选项来源**:协议与地址/端口选项**从当前文件动态提取去重**,不预置全量协议枚举。
- **非 IP 帧降级**:ARP / LLC 等无端口的帧 → 端口维度自动置灰并提示「当前文件含非 IP 帧」。
- **筛选语义 = 会话级**:某会话的任意报文命中条件即命中该会话(见 F3),筛选**收敛会话列表**;时序图展示会话内全部报文。
- 筛选后会话列表顶部显示「命中 N / M 会话」。
- 追加说明:会话内「仅显示匹配报文」开关 → 排入 v1.1。

### F3 会话聚合

- **归一化规则**:
  - TCP / UDP:按五元组做**双向流归并**(A⇄B 视作同一会话),key = `sort((ipA,portA),(ipB,portB))`。
  - ICMP:按 `(ipA, ipB, type)` 归一。
  - ARP / 其他非 IP:按地址(IP 或 MAC)方向归一。
- **客户端 / 服务端判定**(决定时序图左右 lifeline 与方向着色):
  - TCP:先发 **SYN** 者为客户端;无 SYN 则取端口较小端;再退化为首包发送者。
  - UDP:首包发送者为客户端。
  - ICMP / ARP:仅区分方向,不标注客户端。
- **会话列表列**:客户端、服务端、协议(取该会话最高层应用协议,如 HTTP/TLS/DNS)、报文数、字节数、开始时间、时长;默认按开始时间排序,支持列头排序。
- 会话级「协议」标签 = 该会话出现过的应用层协议;若命中多个,展示主协议并允许展开。

### F4 时序图渲染(核心)

**数据**:单个会话的报文(按可见时间升序)。

**双风格 + 一键切换**:
- **风格 A(默认)· flow.png 斜线交叉**:请求一律斜向右下、响应一律斜向左下,中间交叉成 X,方向感强。
- **风格 B · 水平消息行**:每个报文一行,箭头方向表示方向,易读、易扩展。

**端点呈现**:左右两条 lifeline + 顶部端点卡片(IP:端口、角色、总包数);客户端在左、服务端在右。

**每个报文一条有向箭头,标注**:
1. **编号**:会话内按可见时间序 ①②③ …(全局会话内序号)。
2. **可见时间戳**:相对首包 `0.000`(同时提供绝对时间切换)。
3. **协议 + 关键信息**:TCP 标志(SYN/SYN-ACK/ACK/FIN…)、HTTP 方法+URI / 状态码、DNS 查询名、TLS 握手类型等(字段映射见 §13)。
4. **报文长度**(字节)。

**配色规则**:
- **线色 = 协议色**(预设调色板,§13);可选「整线按方向着色」切换。
- **方向色 = 步骤徽章 / 方向符号**:请求徽章蓝 ●、响应徽章橙 ●;箭头方向本身也表达方向。

**交互**:
- **悬停**:高亮该箭头 + tooltip(方向 / 协议 / 源目的 / 长度 / seq / ack / 关键载荷摘要)。
- **点击**:下方详情条展示完整字段与 hex(F5)。
- **缩放**:垂直缩放(报文多时)、横向自适应;顶部显示会话起止时间。
- **可读性兜底**:报文数 > 2000 时提示「建议切换风格 B / 采样显示」。

**图例**:右上角固定图例区(协议色 + 方向色说明)。

### F5 报文详情

- 点击时序图报文 → 右栏底部(或独立面板)详情条。
- 展示层级:**帧概要**(时间 / 长度 / 接口)→ **L2**(源 / 目的 MAC、类型)→ **L3**(IP 版本 / 源 / 目的 / TTL)→ **L4**(TCP 标志 / seq / ack / 窗口,或 UDP 长度)→ **应用层**(HTTP 行与头 / DNS 记录摘要)→ **hex dump**。
- **hex 按需拉取**:打开文件时不做全量 hex;点击某报文时单独调 tshark 获取该报文原始字节(避免拖慢打开)。
- 字段缺失时显示占位「—」。

### F6 时序图导出 PNG

- 工具栏「导出 PNG」→ 将当前时序图(SVG)渲染为 PNG,弹窗保存。
- 命名建议:`<源IP>-<目的IP>-<协议>-<时间>.png`。

### F7 内置示例抓包

- 随安装包附带 2–3 个示例抓包(如:HTTP 会话、DNS 查询、ARP/TCP 握手混合)。
- 「打开示例」入口(如帮助菜单或欢迎页),用于教学/演示与首次体验。

## 7. UI 设计要点

- **三栏常驻布局**(已确认):左筛选 | 中会话列表 | 右时序图;顶部工具条(打开文件 / 文件概览 / 导出 PNG / 风格切换)。

## 9. 架构概述

```
┌──────────────────────────── 前端(React + TS + Vite)────────────────────────────┐
│  状态管理(文件信息 / 筛选 / 会话 / 当前会话 / 选中报文)                            │
│  模块:筛选器 · 会话聚合器 · 时序图渲染器(自绘 SVG,双风格) · 报文详情 · 导出 PNG     │
└───────────────▲───────────────────────────────────────────────┬───────────────┘
                │ @tauri-apps/api invoke(命令)                   │ 数据
┌───────────────┴───────────────────────────────────────────────▼───────────────┐
│                            后端(Rust · 薄)                                     │
│  命令:open_capture(调 tshark) · fetch_hex(报文号) · locate_tshark               │
└───────────────▲───────────────────────────────────────────────────────────────┘
                │ 子进程 + JSON
        ┌───────┴───────┐
        │  tshark 引擎   │  ← 打包内置(可选系统 Wireshark/tshark)
        └───────────────┘
```

- **打开文件**:tshark `-r <file> -T json`(固定字段集,§13)一次性导出全部报文 → 前端解析为 `Packet[]` → 前端聚合会话、前端筛选(文件规模小,无需二次调 tshark)。
- **tshark 定位**:① 随包内置资源 → ② 用户配置路径 → ③ 系统 PATH。
- 时序图:**React 自绘 SVG**,同一数据源 + 两套布局函数实现 A/B 切换(不引入重型图库,精确满足标注/着色/交互需求)。

## 10. 错误处理与边界情况

| 场景 | 行为 |
|---|---|
| 文件无法解析 / 损坏 | 明确错误弹窗(含 tshark 原始错误摘要) |
| tshark 未找到 | 引导设置路径 / 检测 Wireshark 安装目录 |
| 筛选无结果 | 会话列表空态 + 提示「尝试放宽筛选」 |
| 非 IP 帧 | 端口维度置灰 + 提示 |
| 详情字段缺失 | 占位「—」 |
| 导出 PNG 失败 | toast 提示 |
| 超长会话(>2000 报文) | 提示切换风格 B / 采样 |
| 报文详情 hex 拉取失败 | 详情条降级为「hex 不可用」 |

## 11. 数据模型与字段映射

### 11.1 Packet(前端模型)

```ts
interface Packet {
  number: number;        // frame.number
  time: number;          // frame.time_relative
  len: number;           // frame.len
  srcIp?: string;        // ip.src / ipv6.src
  dstIp?: string;        // ip.dst / ipv6.dst
  srcMac?: string;       // eth.src
  dstMac?: string;       // eth.dst
  srcPort?: number;      // tcp.srcport / udp.srcport
  dstPort?: number;      // tcp.dstport / udp.dstport
  proto: string;         // 应用层协议(或 tcp/udp/icmp/arp…)
  info?: string;         // 概要(如 HTTP GET / 或 TCP SYN)
  tcpFlags?: string;     // tcp.flags.str
  tcpSeq?: number;       // tcp.seq_raw
  tcpAck?: number;       // tcp.ack_raw
  httpMethod?: string;   // http.request.method
  httpUri?: string;      // http.request.uri
  httpCode?: string;     // http.response.code
  dnsQuery?: string;     // dns.qry.name
  tlsType?: string;      // tls.handshake.type
  direction: 'request' | 'response' | 'other'; // 依 §F3 客户端判定推导
}
```

### 11.2 Conversation

```ts
interface Conversation {
  id: string;            // 归一化 key
  client: string;        // "ip:port" / "ip"
  server: string;        // "ip:port" / "ip"
  protocol: string;      // 会话主协议
  packetCount: number;
  bytes: number;
  start: number; end: number; duration: number;
  packets: Packet[];     // 按时间升序
}
```

### 11.3 FilterCondition

```ts
interface FilterCondition {
  protocol?: string[];    // OR 内,AND 各维度
  srcIp?: string[];
  dstIp?: string[];
  srcPort?: number[];
  dstPort?: number[];
  negate: boolean;        // 取反
}
```

## 13. 对用户原始想法的分析(附录)

用户在最初提出时聚焦于「筛选 + 时序图」。经分析,补充/修正了以下关键点:

1. **复用 tshark 引擎**(最大决策):自研 pcap 解析只覆盖几十种协议且 pcapng 支持残缺;tshark 提供约 3000 个 dissector、原生 pcapng/gzip、成熟字段体系,边际成本极低。
2. **两级粒度**:直接「筛选→画图」在几十万报文下必然图爆炸;先「会话列表」再「点进会话看报文时序」,才可读。
3. **双向流归一化 + 客户端判定**:一次交互是双向的,A⇄B 必须归并为同一会话;左右 lifeline 与方向着色依赖稳定的客户端/服务端角色。
4. **筛选语义定义**:明确为「命中会话整体」,避免「筛协议=X 后到底画什么」的歧义。
5. **方向色与协议色不打架**:线色=协议、方向用徽章/箭头/可选整线着色,两者并存。
6. **详情 hex 按需拉取**:避免全量 hex 拖慢打开与内存。
7. **非 IP 帧边界**:ARP/ICMP 无端口,筛选 UI 需优雅降级。
8. **内置示例抓包**:支撑教学/演示场景开箱即用。
9. **纯本地隐私**:抓包含敏感数据,明确不联网。
