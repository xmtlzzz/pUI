# M4 案例 1：Gap + Dup ACK×3 + SACK + 重传 + 恢复（对照正常连续发送与 ACK 前进）

> 数据来源：`docs/specs/m4-cases/data/case-1-gap-sack.json`（合成抓包经真实 tshark `-o tcp.relative_sequence_numbers:FALSE` 与生产引擎 `analyzeStream`/`detectTcpEvents` 冻结输出）。右栏形状参照 `reference-normal.json`，仅为示意。
> 事件 id：`0:c2s:possible-loss-or-delay:101` · kind=`possible-loss-or-delay` · severity=`medium` · recovered=`true` · evidenceScore=`15` · 方向 c2s · 0.05s–0.25s。

## 1b. 指南规范链与本案例报文的对应

指南第 5/10 节的规范链 `Original Segment → ACK 停滞 → DupACK → SACK → Retransmission → ACK Forward` 在本案例中的逐节点落位：

| 规范节点 | 本案例证据 | observation id |
|---|---|---|
| Original Segment | #6，seq=201，len=100（越过缺口到达） | o1 |
| ACK 停滞 | 累计 ACK 停在 101（#7/#9/#11 三次） | o2/o3/o4 |
| SACK | #7 报告 201–301；随后增长至 201–401（#9）、201–501（#11） | o5 |
| Retransmission | #12，seq=101，len=100（tshark 标注 retransmission） | o6/o7 |
| ACK Forward | #13，ACK 一次前进到 501 | o8 |

指南第 11 节 Timeline 的折叠规则同样适用：三个 DupACK（#7/#9/#11）在时间线上折叠为一个节点展开为 chips，避免重复占屏；每个 chip 保留独立包号以便跳包。

入口路径：会话异常标签 / Top Event 列表中点击该事件 / 报文详情中任一关键报文（#6/#7/#12 等）的"查看事件上下文"，均可携带事件 id 进入本页；返回时恢复原上下文。

## 3. GSAP 动画分镜（按真实事件链时序）

总时长约 3.6s（即下表 S1–S8 时长之和）；所有动画只操作 `transform/opacity`（位移沿时间轴与序列轴两个既定轨道），**不改变任何元素占位尺寸，布局零回流**。每个分镜右侧同步高亮对应的正常参考阶段（联动规则见表末）。

| # | 分镜（触发时刻） | 动画内容 | 时长/缓动 | 右侧联动高亮 |
|---|---|---|---|---|
| S1 | 基线正常（t=0.03–0.04） | #4（seq 1,100B）沿 c2s 轨道飞入落位；#5 的 ACK 游标从 1 推进到 101 | 0.45s ease-out | 步骤① 及其 ACK 刻度点亮 |
| S2 | Gap 显露（t=0.05） | #6（seq 201,100B）飞入，精确落在 201–301 位置；101–201 区间红色 hatch 显露并脉冲一次——让"被越过的字节"可见 | 0.35s ease-in | 步骤② 对比强调：正常流中该位置应先于 #6 到达 |
| S3 | DupACK#1 + 首个 SACK（t=0.06） | #7 沿 s2c 轨道飞入，ACK 游标在 101 处"顿住"不动；序列条上叠加绿色 SACK 块 201–301 | 0.40s power1.out | ACK 轨道上 101→201 段做灰色虚线对比（示意：正常应已前进） |
| S4 | 连续到达、SACK 逐块增长（t=0.07–0.10） | #8、#10 依次落位 301–401、401–501；#9/#11 的 ACK 仍停 101；SACK 块宽度补间 201–301 → 201–401 → 201–501 | 0.80s 两拍 power2.out | 步骤③④⑤ 依序点亮，ACK 游标匀速步进 |
| S5 | 快重传触发点标记 | #11 chip 高亮（dupNum=3），事件卡浮现"3 个重复 ACK（快重传触发条件）"信号标签 | 0.25s pulse ×1 | — |
| S6 | 重传回补（t=0.25） | 时间轴压缩跳变（抓包时刻 0.05→0.25，把 0.20s 的等待压缩为视觉跳跃，角标注明"缺口存续 0.20s"，取自 `durationSeconds`）；#12 沿 c2s 轨道飞入，几何上精确覆盖 101–201，hatch 替换为填补色 | 0.55s power2.inOut | 步骤②–⑤ 保持常亮（正常流无需此步骤） |
| S7 | 恢复（t=0.26） | #13 飞入，ACK 游标从 101 **一次横扫推进到 501**；Gap 带收拢消失 | 0.50s back.out(1.2) | ACK 轨道终点 501 同步对齐闪光 |
| S8 | 收束 | 事件卡"进行中"→"已恢复"，关键报文链 6 枚 chips 全部点亮，evidenceScore 15 浮现 | 0.30s fade | 右栏整体降低透明度，突出左栏结论 |

播放控制硬性约束：

- **可暂停**（Space）、**可单步**（←/→ 逐分镜）、**可中断**（Esc 或切换选中事件时 `kill()` 当前 tween 并清理时间轴，不留残影）。
- 动画**不承载唯一信息**：S2–S7 的全部信息（Gap 带、SACK 块、重传箭头、ACK 游标位置、等待时长）在静态视图中同样完整存在。
- **reduced-motion / 无动画模式**：跳过 S1–S8 直接渲染终态——即第 2 节静态布局所示图形（含 Gap hatch、三块 SACK 叠加、#12 回补箭头、游标位于 501、事件卡"已恢复"）。静态终态与动画结束态信息完全等价，仅缺少运动过程本身。

## 5. 数据保真声明

| 侧 | 数值性质 | 具体内容 |
|---|---|---|
| 左栏 | **真实**（来自 `case-1-gap-sack.json`） | 包号 #1–#13、`seq_raw`/`ack_raw`、SACK 区间 201–301/201–401/201–501、时间戳（0.05/0.25/0.26 等）、Gap 生命周期字段（firstObservedPacket=6、filledByPacket=12、durationSeconds=0.2）、seenBytes c2s=501、observations o1–o8、limitations 原文 |
| 右栏 | **解释性示意** | 形状取自 `reference-normal.json` 的形态（握手 → 5 段×100B 连续发送 → 每段被顺序确认 ACK 101→201→301→401→501 → 干净关闭；零 Gap、零事件），仅用于解释"同类交互应有的样子" |

- 右栏固定徽标「正常参考/示意」**不可关闭**；右栏使用步骤编号 ①–⑤，**不出现任何真实 packet number**。
- 右栏内容**永不进入** Observations、Inference 的 evidenceRefs、Limitations 或报告导出——它是 UI 解释层，不是证据层。这与计划第 8 节风险项「正常参考被误认成抓包事实」及第 10 节审批口径一致。
- 措辞遵循引擎输出：只说"数据未及时到达"，不断言确定性丢包；两条 limitation（单观察点、无法排除抓包自身漏包）必须始终随事件展示。
